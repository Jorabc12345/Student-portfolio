# Navigation Requirements

## Shared Navigation

Authentication state determines the shell. Unauthenticated users see only entry/authentication screens. Authenticated users see role-appropriate navigation; no shell control may be treated as authorization.

## Student Navigation

Recommended primary structure:

1. Home / Portfolio.
2. Level 1.
   - MED 101.
   - MED 102.
   - MED 103.
   - PLO Attainment.
   - Final Musings.
3. Artifacts.
4. Reviews and Feedback.
5. Access Management.
6. Profile / Settings.

Within a subject: subject overview → four main folders → reflection prompts and artifacts. MED 102 must offer a domain index or equivalent direct route so all eight domains remain separately accessible.

## Instructor Navigation

1. Authorized Portfolios.
2. Selected Portfolio.
3. Subject/Folder/Domain navigation.
4. Reviews and Feedback.
5. Instructor Profile.

Do not show a directory of all instructors or students. Empty authorized-portfolio state must explain how a student authorization enables access without exposing other users.

## Client Administrator Navigation

1. Invitation Code.
2. Code lifecycle/status.
3. Account/logout.

No general portfolio or academic-content navigation is included.

## Breadcrumbs and Context

Reflection and artifact screens should show Level → subject → folder → domain/prompt context. Review/feedback screens should show portfolio owner context only after authorization. Back navigation must preserve unsaved-change warnings and return users to their prior academic location.
