# User Roles and Experience

## Student / Portfolio Owner

### Goals

- Build a coherent professional and reflective portfolio.
- Navigate Level 1 subjects and domains.
- Answer official reflection questions.
- Connect artifacts to reflections, domains, and PLOs.
- Control who can view the portfolio.
- Read instructor reviews and feedback.

### Permissions and limits

Students manage only their own profile, portfolio content, artifacts, reflections, global sections, PLO evidence, access grants, and revocations. They cannot change academic configuration, grant themselves Instructor roles, or access another student's portfolio.

### Experience principles

Use progress as orientation rather than grading. Preserve context while writing. Make privacy and ownership visible. Avoid dashboard metrics that imply clinical grading or competition.

## Instructor

### Goals

- Register securely with the current invitation code.
- View portfolios explicitly authorized by students.
- Review learning progress and evidence.
- Provide constructive, contextual guidance.

### Permissions and limits

Instructors can view authorized content and create reviews/feedback. They cannot edit, upload, delete, grade, or alter original student content. Replacing or disabling the invitation code does not remove existing accounts or authorizations.

### Experience principles

Clearly label read-only student content. Separate “review notes” and “feedback” from original answers. Show authorization status and access expiry/revocation state without exposing unrelated students.

## Client Administrator

### Goals

- Generate or replace the shared faculty invitation code.
- Disable the current code.
- See current code status and lifecycle events.

### Permissions and limits

Only the invitation-code operation is in scope. The client administrator does not automatically gain access to portfolios, edit student work, manage academic content, or grade students unless separately approved.

### Experience principles

Show the code only at the controlled reveal/copy moment, warn that replacement invalidates future registrations, and never display historical plaintext codes.
